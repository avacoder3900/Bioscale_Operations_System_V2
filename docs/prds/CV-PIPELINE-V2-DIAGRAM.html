The V2 pipeline

Five stages, one model lifecycle

Every trained model becomes an immutable version that moves through a lifecycle — new training adds versions, never erases them. Rollback is repointing, not retraining.

trained→ verified→ deployed→ retired · gate between trained→verified: holdout sample ≥ min count AND balanced accuracy ≥ min — only verified versions get a Deploy button
1

Capture — phase picks the model V2

src\routes\api\cv\capture\+server.ts → src\lib\server\cv\run-inference.ts

Capture keeps its contract (orphan photos rejected, atomic image numbering, R2 upload, photo ref pushed to the cartridge). The photo's phase is the routing key: after saving, capture looks up which deployed model owns that step — a post-mortem photo is checked by the post-mortem model, wax by wax — via find({ deployAtPhases: phase, activeModelVersion: {$ne: null} }).

  • The response and inspect pages say exactly which project + version graded the photo, or that nothing is deployed at this step.
  • New: if the capture comes from a station whose assignedPhase disagrees with the posted phase, the operator gets a warning (catches wrong-station mistakes; doesn't block).

Label — two doors, one field V2

api\cv\capture (verdict at capture) · src\routes\cv\label · image-stream review UI

Approve/reject can happen at the moment of capture (new optional verdict field on the capture call, next to the existing failure-label tagging) or later in /cv/label and the stream UI. Both write the same single source of truth: qcLabel, attributed with qcLabeledBy/At. The trainer reads only this field; the legacy label field is migrated into it and retired.

3

Train — where the verdict is made core of V2

src\lib\server\services\cv-bridge.ts (triggerTraining, in-process: sharp embeddings + logistic regression)

Training-set assembly replaces the naive label query. At train time the project resolves: all images with qcLabel set, whose cartridgeTag.phase matches the project's phases, joined against the cartridge to apply trainingFilter — cartridge statuses to include (e.g. exclude voided carts), required/excluded failure tags. Then it embeds (156-feature color/spatial vector, cached per image), fits logistic regression, and calibrates the pass threshold.

Output is an appended, immutable version — not an overwrite. Each run adds a trainedModels[] entry carrying its own weights and its training-set manifest: exactly which imageIds trained it, class counts, and newSincePrevious so you can see what each iteration added. The train UI shows "N labeled available, M new since current version" before you press Train — so you never retrain on the same set by accident, and more photos improve the next version without touching any previous one.

4

Verify → Deploy — the gate and the button V2

Deployment tab · src\routes\cv\projects\[id]\+page.server.ts

Verify: assembly holds out a stratified sample (default 20%, min 5 per class) the fit never sees. The candidate is scored on it and the result lands inside the version entry. Only a version whose holdout meets the gate — minimum sample size and minimum balanced accuracy (defaults 10 / 0.80, per-project override) — flips to verified. A quick-check panel can re-verify any version against the current labeled pool on demand.

Deploy: the Deploy button is enabled only for verified versions. Deploying sets activeModelVersion and deployAtPhases (wax / reagent / post-mortem…), marks the version deployed, and retires the previous one — status only, weights kept, so rollback is one click. A shadowModelVersion can run silently alongside for A/B before promotion. Every deploy is audit-logged.

5

Review — close the loop V2

/cv/stream review · cv_inspections

Every deployed-model run stays a CvInspection doc — the verdict log (one per image × project × version, shadows flagged). Operators review verdicts in the stream section; a review writes humanLabel on the inspection and mirrors into the image's qcLabel, which feeds stage 3's next iteration. A per-version scorecard (model verdict vs. human review agreement) tells you when the deployed version is drifting and it's time to train the next one.

  • New — needs-review queue: a dedicated view of every image with a model verdict but no human review yet (result != null, humanLabel == null, shadows excluded), newest first, filterable by project/phase. Thumbnail + PASS/FAIL badge + one-click Agree / Overrule; the queue count shows as a badge in the CV nav so nothing sits unreviewed unnoticed.
  • New: a compact verdict summary {verdict, inspectionId, modelVersion} is mirrored onto the matching cartridge_records.photos[] entry, so cartridge/DHR pages show pass–fail without extra queries. Summary only — labels, embeddings and history never move onto the cartridge doc.
